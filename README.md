# PICO 프론트엔드 전달 안내

## 어떤 코드인가요?
HTML + CSS + Vanilla JavaScript(ES Modules)로 만든 PC 웹 프로토타입입니다.
React, Vue, TypeScript, 별도 번들러를 사용하지 않습니다.
`dist`는 압축된 결과물이 아니라 직접 수정할 수 있는 원본 화면 코드입니다.
Node.js 서버는 정적 파일을 제공하는 용도이며 업무용 백엔드가 아닙니다.

## 실행 방법
1. Node.js 20 이상이 설치된 컴퓨터에서 ZIP을 압축 해제합니다.
2. 압축을 푼 폴더에서 터미널을 엽니다.
3. `npm start` 또는 `node server.mjs`를 실행합니다. 추가 패키지 설치는 필요 없습니다.
4. 앱: http://127.0.0.1:4173/index.html
5. 화면별 검토: http://127.0.0.1:4173/handoff.html

HTML 파일을 더블클릭하지 말고 서버로 실행하세요. ES Module과 브라우저 저장 기능을 사용합니다.
4173 포트가 이미 사용 중이면 기존 서버를 종료하거나 server.mjs의 포트를 바꾸세요.
Pretendard 글꼴은 외부 CDN에서 로드하며, 연결되지 않으면 대체 글꼴로 표시됩니다.

## 주요 파일
| 파일 | 역할 |
| --- | --- |
| dist/index.html | 앱 시작 페이지 |
| dist/app.js | 상태, 라우팅, 헤더·푸터, 공통 모달 |
| dist/account.js | 로그인·가입·도우미 신청·마이페이지·문의 |
| dist/recovery.js | 아이디 찾기·비밀번호 재설정 체험 |
| dist/discovery.js, discovery-filters.js | 도우미 검색·필터·프로필 |
| dist/transactions.js | 요청·매칭·조건 합의·결제·결과 흐름 |
| dist/data.js | 예시 도우미·거래 데이터 |
| dist/ui.js, pc-interactions.js | 공통 UI와 상단 메뉴 |
| dist/pc-refinements.css | 최신 PC 디자인 조정, 마지막에 적용되는 CSS |
| dist/styles.css, account.css, transactions.css, desktop.css | 기존 스타일과 화면별 스타일 |
| dist/handoff.html, handoff.js | 상태별 화면 검토용 목록 |
| server.mjs | 로컬 정적 파일 서버 |

## 검토 방법
- 실제 탐색 흐름은 index.html에서 확인합니다. 로그인 화면 아래 '예시 계정으로 로그인'을 사용할 수 있습니다.
- handoff.html은 각 단계의 예시 상태를 바로 여는 검토 도구입니다. 화면을 다시 선택하면 상태가 초기화될 수 있습니다.
- 예매 가능 날짜, 문의 작성·현황, 계정 찾기는 해당 앱 메뉴에서 이동해 확인할 수 있습니다.
- PC 기준으로 수정한 화면입니다. 모바일 레이아웃은 이번 작업 범위 밖입니다.

## 구현 범위와 후속 개발
화면, 입력 검증, 상태 전환, 브라우저 내 저장, 다중 날짜 선택, 후기·좋아요, 항목별 결제 체험이 구현되어 있습니다.
현재 실제 회원 서버·DB·OAuth·휴대전화/이메일 발송·결제/정산·상담 시스템은 연결되어 있지 않습니다.
인증번호 123456은 체험용이며, 로컬 비밀번호 처리 역시 운영 서비스의 인증 보안을 대신하지 않습니다.
문의는 브라우저에만 저장됩니다. 첨부파일은 브라우저 내 저장으로 처리합니다.
방문자 사이의 계정·요청·거래 상태는 공유되지 않습니다. 작업자의 브라우저 저장 데이터도 이 ZIP에 포함되지 않습니다.
운영 개발 시 서버 인증·권한 검사, 데이터베이스, 결제사, 메시지 발송, 업로드 저장소 등을 연결해야 합니다.

## 개별 결제 동작
착수금·성공비가 기본 선택됩니다. 개별로 결제하면 완료한 항목은 다시 선택할 수 없습니다.
두 항목 결제가 모두 완료되기 전에는 거래가 결제 대기 상태로 남습니다.
체험상 수수료는 성공비 결제 시 한 번만 적용합니다(성공비 3%, 최소 1,000원).
실제 금액 청구나 환불·정산은 실행하지 않습니다.

## 다른 프레임워크로 개발할 경우
이 코드를 화면/동작 명세로 사용해 React, Vue 등으로 옮길 수 있습니다.
기존 앱이 해당 프레임워크로 구현되어 있는 것은 아니므로 컴포넌트 분리와 상태 구조 전환 작업이 필요합니다.

## 배포
정적 호스팅의 공개 디렉터리를 dist로 지정하면 됩니다. 빌드 명령은 필요 없습니다.
화면 라우팅은 URL의 # 해시를 사용합니다. server.mjs를 업무용 API 서버로 배포하지 마세요.
