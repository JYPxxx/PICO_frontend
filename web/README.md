# PICO 웹 (React)

백엔드 API와 연결하는 PICO 웹 프론트엔드입니다.

- 동작 기준: API 명세(`openapi.json`)와 백엔드 서비스 흐름 가이드(`DEMODAY_백엔드_서비스흐름.pdf`, 코드 `2d8b602`). 둘이 다르면 가이드를 따릅니다.
- 화면 기준: 상위 폴더의 `dist/` 프로토타입. 프로토타입과 명세가 다르면 명세를 따릅니다.
- 달라진 흐름, 백엔드·기획 요청 사항, 구현 현황은 [`API_NOTES.md`](API_NOTES.md)에 있습니다.

## 실제 백엔드에 연결

```
npm install
cp .env.example .env.local   # API_PROXY_TARGET에 백엔드 주소 입력
npm run dev                  # http://localhost:5173
```

1. `/dev/api` 화면에서 `GET /api/health`, `GET /api/policies`, `GET /api/platforms` 응답이 오는지 확인합니다.
2. 약관 3종·예매처·관리자 계정·테스트 도우미가 준비되어 있어야 전체 흐름이 진행됩니다(`API_NOTES.md` 1-1).
3. 서버에 약관이 아직 없으면 `.env.local`의 `VITE_FALLBACK_*_ID`에 서버의 실제 문서 번호를 넣습니다(임시). 약관이 등록되면 지웁니다.
4. 운영팀 작업(요청 정책 검토, 증빙 파일 검토, 도우미 심사, 분쟁 확정, 약관·예매처 등록 등)은 관리자 계정으로 로그인해 `/admin` 화면에서 합니다. 메뉴에는 없고 주소로 들어가며, 권한은 서버가 검사합니다(관리자가 아니면 403).
5. 안전거래(가상계좌)는 백엔드에서 아직 503이라, 최종 조건을 **직접 거래**로 보내야 끝까지 진행됩니다.
6. 화면 값이 비거나 단계가 이상하면 `/dev/api`에서 응답을 확인합니다. 대부분 응답 필드명 차이이고, 필드 후보는 `src/discovery/agent.ts`, `src/transactions/model.ts`, `src/agent/profile.ts`의 `pick()` 호출에 있습니다.

백엔드 명세가 바뀌면 `openapi.json`을 교체하고 `npm run api:types`로 타입을 다시 생성합니다.

## 백엔드 없이 실행 (목 서버)

```
npm run dev:mock             # 목 서버(:8090) + 개발 서버를 함께 실행
```

- `mock/server.mjs`가 API 명세 형식으로 응답하는 가짜 백엔드예요. 데이터는 메모리에만 있어 끄면 초기화돼요. 개발 코드(`src/`)와 분리되어 있고 빌드에 포함되지 않아요.
- 예시 계정(비밀번호 모두 `password1234`): 이용자 `demo@pico.test`, 도우미 `agent1@pico.test` ~ `agent6@pico.test` (도우미 찾기 목록 순서와 같음, 매칭권 3장씩)
- 이용자와 도우미를 함께 보려면 브라우저 창 두 개(일반 창 + 시크릿 창)로 각각 로그인하세요. 거래 화면은 창으로 돌아오면 다시 불러와요.
- 실제 백엔드와 다른 점
  - 운영팀 작업을 자동 처리: 요청 정책 검토 자동 허용, 도우미 신청은 제출 5초 뒤 자동 승인(`MOCK_APPROVE_MS`로 조정)
  - 외부 연동을 흉내 냄: 본인인증은 인증창 없이 통과, 계좌는 8자리 이상이면 통과, 가상계좌는 '입금 확인'을 누르면 입금된 것으로, 매칭권 결제는 결제창 없이 승인, 착수비·성공보수 지급 기록을 바로 만듦
  - 메일 대신 목 서버 터미널에 `[mock] ✉ … 링크`(이메일 인증·변경, 비밀번호 재설정)가 찍혀요. 그 주소를 브라우저에서 열면 돼요.
  - 요청 상태 변경 알림(새 요청, 수락, 합의 제안, 착수, 결과)을 보내요. 실제 백엔드는 아직 이 알림이 없어요.
  - 아직 가이드 규칙을 반영하지 않은 부분: 서버 `stage` 응답, 결과·경력 증빙 파일 검토(CLEAN), 부분성공 정산, 환불, 신고(501)
- 응답 필드명은 프론트가 찾는 이름으로 정한 거예요. 실제 백엔드와 다를 수 있으니 연결 테스트를 대신하지 않아요.

## 구조

```
src/api/           API 클라이언트(client.ts), 토큰(tokens.ts), 약관(policies.ts), PortOne(portone.ts), 응답 필드 찾기(pick.ts), 생성된 타입(schema.d.ts)
src/auth/          로그인 상태, 로그인 필요 화면 보호
src/layout/        공통 셸(헤더·알림·프로필 팝오버·푸터)
src/discovery/     도우미 찾기(카드, 필터, 달력, 검색 API, 좋아요)
src/transactions/  거래 모델·단계 판단(model.ts), 거래 화면 공통 부품(ui.tsx), 부분성공 정산·환불(Settlement.tsx)
src/agent/         도우미 프로필 버전·인증·경력 증빙
src/ui/            공통 부품(아이콘, 모달, 토스트, 페이지 제목, 계정 화면 부품)
src/pages/         화면
src/styles/        프로토타입 CSS 원본(수정은 pc-refinements.css 끝에 주석과 함께)
mock/              목 서버(개발용, 빌드 제외)
```
